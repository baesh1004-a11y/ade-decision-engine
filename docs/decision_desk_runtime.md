# Decision Desk 런타임 구현

기준: 2026-09-10. 64개 엔진 설계 중 공통 실행 기록과 실제 사용 화면의 연결을 구현한 범위다.

## 사용자 흐름

1. 한국/미국 시장과 검토할 완료 추천 실행을 선택한다. 새 계산 중에도 기존 선택은 유지한다.
2. 저장된 순위의 종목 목록에서 종목을 선택한다. 검색은 표시만 거르며 순위를 재계산하지 않는다.
3. 추천의 `recent_event_date`까지 현재 120거래일을 읽고, 해당 급등 사례의 직전 120거래일과 비교한다. 시세 출처는 하나로 고정한다. 사례가 모호하거나 이력이 부족하면 경고를 표시한다.
4. 가격·거래량, STO 단·중·장기 마지막 6주 경로, 저장된 사례 성과를 전환한다. STO는 기존 추출 엔진을 사용한다.
5. 선택적으로 시장·업종 환경을 확인하고 판단 메모를 저장한다. 환경 검토는 추천 점수나 순위를 바꾸지 않는다.
6. 추천 실행과 순위를 포함해 주문 후보로 전달한다. 한국은 기존 모의주문 티켓, 미국은 USD 지정가 요청·승인 흐름을 사용한다. 후보 저장은 브로커 주문을 전송하지 않는다.
7. 주문 화면에서 원래 추천과 검토 메모로 돌아올 수 있다.

추천 0건은 유효한 완료 결과다. 이전 결과를 최신인 것처럼 대신 표시하지 않는다. 기존 실행 중 시장을 식별할 수 없는 빈 결과는 다른 시장의 결과로 추정하지 않는다.

## 책임 경계

| 위치 | 책임 |
|---|---|
| `dashboard/decision_desk.py` | 화면 구성, 명시적 경로 선택, 실행·종목 선택 상태 |
| `dashboard/desk_data.py` | SQLite 읽기 전용 조회와 비교 자료 구성 |
| `dashboard/desk_charts.py` | 같은 기준축의 가격·거래량과 기존 STO 경로 표시 |
| `dashboard/desk_review.py` | 기존 세션 소유자별 추천 검토 기록 |
| `dashboard/desk_orders.py` | 미국 후보를 기존 USD 주문 요청·승인 기능에 연결 |
| `core/run_models.py` | 실행 요청·단계·결과 계약과 JSON 해시 |
| `core/run_state_store.py` | 단계 순서·종료 상태 검사, 트랜잭션, 중복 요청과 산출물 무결성 |
| `core/orchestrator.py` | 기존 `ADEPipeline`의 입력 확인·판단·결과 저장 |
| `recommendation/daily_service.py` | 기존 추천 계산·보고서·저장을 같은 실행 번호로 기록 |
| `recommendation/validation_service.py` | 종목별 환경 검토와 이후 성과 관찰 등록 |

기본 진입점은 `dashboard_app.py`다. 예전 진입점의 전역 함수 교체 대신 명시적으로 필요한 화면을 호출한다. 상황종합판의 시장 표시도 콜백 인자로 주입해 세션 간 전역 함수 변경을 없앴다. 기존 JP Radar와 Replay Watch는 해당 기능을 유지한다.

## 저장과 실행 계약

- `ADE_DATA_DIR/market.db`, `ADE_DATA_DIR/us_market.db`에 `ade_runs`, `ade_run_stages`, `ade_run_artifacts`, `ade_schema_migrations`를 추가한다. 기본 디렉터리는 `datahub`다.
- 기존 추천 테이블과 자료는 보존하고 `recommendation_runs.market`를 추가한다. 기존 추천 행으로 시장을 확인할 수 있는 기록은 계속 조회한다.
- 추천 성공 시 기존 추천 행·완료 상태·마지막 단계 산출물을 같은 연결과 트랜잭션으로 저장한다. 저장 실패 시 추천 행을 롤백하고 생성 보고서를 제거한다.
- 환경 검토는 원래 추천 순위로 해당 종목만 갱신한다. 저장과 단계 산출물은 원자적으로 처리한다. 성과 관찰 등록만 실패하면 환경 검토를 보존하고 `PARTIAL_SUCCESS`로 기록한다.
- 종료한 실행을 같은 번호로 다시 시작하지 않는다. 단계는 선행 단계 완료 후 시작하며 JSON 산출물은 해시를 확인한다. 해시는 암호학적 서명이나 외부 원장 대사를 대체하지 않는다.
- `/decision`의 `idempotency_key`가 같고 입력이 같으면 저장 결과를 반환한다. 입력이 달라지면 거절한다. 실행 중 또는 실패한 요청의 자동 재시도·이어 실행은 제공하지 않는다.
- 기존 응답의 `decisions` 등 필드는 유지하고 `run: {run_id, status}`를 추가한다. 원래 입력 `DecisionContext`를 복사해 엔진의 내부 갱신이 호출자 입력을 바꾸지 않도록 했다.
- 메모와 주문 후보는 `ADE_UI_STATE_DB`에 저장한다. 기본값은 `output/ade_ui_state.sqlite3`다. 주문 후보 스키마 v3는 `source_run_id`, `source_rank`를 추가한다.

## 검증

로컬 결과: 전체 186개 테스트 통과, Ruff 검사와 컴파일·진입점 가져오기 검사 통과. 외부 API와 브라우저 시각 검증 결과를 뜻하지 않는다.

```bash
pip install -r requirements.lock.txt
python -m pytest -q
ruff check broker dashboard datahub markets recommendation jp_radar core api tests
python -m compileall -q .
```

주요 회귀 검증은 다음을 포함한다.

- 실제 `ADEPipeline`과 기록 래퍼의 판단 결과 일치, 입력 보존, API 요청 재사용.
- 단계 순서, 종료 상태 불변, 중첩 롤백, JSON 변조 감지.
- 추천 성공·0건·중단·실패와 결과 저장 실패의 원자성.
- 다른 종목의 환경 검토 보존과 성과 관찰 실패의 부분 완료 처리.
- 추천 이후 시세 제외, 출처 혼합 방지, 모호한 과거 사례 표시.
- Streamlit에서 시장 전환, 실행 선택 유지, 빈 결과 표시, 메모 저장, 한국/미국 주문 후보 이동과 복귀.
- UI 검증에서 외부 HTTP를 차단하고 실제 주문이 생성·전송되지 않는지 확인한다.

배포와 CI가 같은 선언 버전을 사용하도록 `requirements.txt`에 제약 파일을 연결했다. 기존 화면이 사용하는 `width` API를 지원하는 Streamlit 1.54.0을 고정했다. AppTest의 단일 선택 `ButtonGroup`은 테스트에서 문서화된 리스트 입력으로 직렬화한다. 근거: [Streamlit 2026 릴리스 기록](https://docs.streamlit.io/develop/quick-reference/release-notes/2026).

기존 실패 테스트 중 시간대 없는 주문 시각, 미래에 남아 있는 예약 `next_check_at`, 과거 비교창 밖의 수동 기준일은 테스트 자료를 실제 계약에 맞게 수정했다. 주문 만료와 예약 대기, Replay 기간 제한을 완화하지 않았다. 차트 검증은 소스 문자열 대신 실제 상승·하락 색과 표시 높이를 확인한다.

## 남은 범위

- 클라우드 DB 이전과 운영 저장소 백업·복구는 이번 변경에 포함하지 않는다. Render의 영구 디스크/외부 저장소가 없으면 재배포 시 SQLite 자료를 잃을 수 있다.
- 메모의 소유자 구분은 기존 Streamlit 세션 식별자를 사용한다. 로그인 계정과 여러 기기 간 동기화는 후속 작업이다.
- 공통 실행 기록은 추천·종합 판단·환경 검토를 포함한다. 브로커 주문·부분체결·잔고 대사를 하나의 원장으로 통합하는 작업은 남아 있다.
- 원천 가격 자료 전체와 정책·모델 버전을 불변 스냅샷으로 보관하는 기능은 아직 없다. 비교 자료는 저장된 추천 시점으로 제한하지만 원천 DB의 사후 정정까지 고정하지는 않는다.
- 프로세스 강제 종료 후 실행 복구, 단계 재시도, 전체 워크플로 스케줄러는 후속 범위다.
- 실제 KIS 계좌·주문, 운영 규모 추천 계산, 브라우저 시각 검증은 수행하지 않았다. 기존 운영 배포 흐름은 유지한다.
