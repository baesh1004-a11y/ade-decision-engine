# ADE 추천엔진 최적화 원칙 및 적용 기록

## 불변 알고리즘 원칙

- 전체 활성 종목을 동일 기준으로 비교한다.
- 최근 120거래일을 과거 실제 급등 직전 120거래일 패턴과 비교한다.
- 주봉 유사도 계산식과 가중치는 변경하지 않는다.
- STO 3계층 궤적 유사도 계산식과 가중치는 변경하지 않는다.
- 주봉 최소 기준과 STO 최소 기준을 모두 통과한 후보만 추천한다.
- 추천 순위는 기존 주봉 유사도 기준과 기존 tie-break 규칙을 유지한다.
- 패턴 수, 종목 수, 필터 기준을 성능을 이유로 임의 축소하지 않는다.

## 현재까지 적용한 무손실 최적화

1. 추천결과 화면의 불필요한 시장·뉴스·상태 조회를 지연 실행으로 변경했다.
2. 추천 실행 설정값을 버튼 클릭 순간 확정해 UI → Job → Engine 전달값을 추적한다.
3. 추천 실행 성능 로그를 추가했다.
   - DB hit/miss, 외부 조회 수
   - 패턴·종목·가격·특징·주봉·STO·정렬·전체 시간
   - 느린 종목 상위 10개
4. 가격 데이터를 종목별 반복 SQL 대신 시장 전체 최근 120거래일 일괄 조회로 변경했다.
5. 백업 브랜치 `backup/pre-bulk-recommendation-20260802`를 생성했다.

## 다음 최적화 원칙

다음 단계는 특징 캐시다. 캐시 키는 최소한 다음을 포함해야 한다.

- market
- ticker
- latest_trade_date
- feature_version
- source/data version when needed

캐시된 WeeklyShape와 STOStructure는 기존 `to_dict()` 결과를 그대로 JSON 저장하고, 복원 시 동일 dataclass를 생성한다. 캐시 적중 여부만 달라져야 하며 계산식과 최종 결과는 달라지면 안 된다.

## 검증 조건

최적화 전후 동일 입력에서 다음이 완전히 같아야 한다.

- 최종 추천 티커와 순위
- weekly_similarity
- sto_similarity
- final_similarity
- matched_event_id 및 matched_event_date
- 추천 사유에 사용되는 대표 과거 사례

하나라도 달라지면 성능 최적화가 아니라 알고리즘 변경으로 간주하고 되돌린다.
